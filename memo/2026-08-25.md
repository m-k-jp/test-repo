---
title: 配色の切り替えを3スコープで組む
tags: [CSS, アクセシビリティ]
---

ライト / ダーク / システムに従う の3択を作った。CSS の書き方に少し工夫が要る。

## 定義は3か所に分かれる

```css
:root { ... }                                 /* ① ライト（既定） */

@media (prefers-color-scheme: dark) {
  :root:not([data-theme="light"]) { ... }     /* ② OS がダーク */
}

:root[data-theme="dark"] { ... }              /* ③ 明示的にダーク */
```

肝は②に付けた `:not([data-theme="light"])` で、これが無いと「OS がダークの人が明示的にライトを選ぶ」ができない。**手動選択がメディアクエリに勝つ**必要がある。

## 一番の敵はチラつき

ダーク設定の人がページを開いたとき、一瞬白い画面が見えてしまうのがこの手の実装の典型的な失敗になる。保存値を読むのが最初の描画に間に合わないために起きる。

Astro が通常生成する `<script>` は `type="module"` になり**遅延実行**されるので間に合わない。`is:inline` を使って `<head>` 内で即時実行させる。

```astro
<script is:inline>
  (function () {
    const root = document.documentElement;
    try {
      const saved = localStorage.getItem('theme');
      if (saved === 'dark' || saved === 'light') root.dataset.theme = saved;
    } catch {}
  })();
</script>
```

「OS はライトだがダークを保存済み」という最悪ケースで描画初期を連写して測ったところ、白は一度も観測されなかった。

## 状態管理に `aria-pressed` を使う

ボタンの選択状態を `class="active"` のような見た目専用のクラスで持つと、アクセシビリティ属性と別管理になり、**両者がずれる**バグが起きる。

```js
buttons.forEach((b) => b.setAttribute('aria-pressed', String(b.dataset.mode === mode)));
```

```css
button[aria-pressed='true'] { background: var(--surface-2); }
```

属性を1つに統一すれば、構造的にずれようがない。支援技術への通知と CSS のセレクタを同じものが担う。

## canvas だけは別扱い

グラフは `<canvas>` に描くため CSS 変数が効かない。切り替え時にイベントを飛ばして再描画している。

```js
window.dispatchEvent(new CustomEvent('themechange', { detail: { mode } }));
```

CSS なら自動で追従するところを、canvas では手動でやる必要がある。
