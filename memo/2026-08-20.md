Astro のアイランドは「画面に入るまで JS を読み込まない」と説明される。本当にそうなのか、3D デモページで実測した。

## 測り方

ヘッドレス Chromium でページを開き、転送されたリソースを記録する。スクロール前と後で比較すれば、遅延読み込みが効いているかが分かる。

```js
page.on('response', async (r) => {
  rows.push({ phase, url: r.url(), bytes: (await r.body()).length });
});
```

## 結果

| 段階 | 読み込まれたもの |
|---|---|
| 初回 | `index.html` 11,077 B / `favicon.svg` 196 B |
| スクロール後 | JS 5 ファイル 計 542,298 B |

**初回に読み込まれる JavaScript は 0 バイトだった。** Preact のランタイムすら含まれていない。

スクロールして 3D が画面に入った瞬間に、はじめて three.js（523,431 B）を含む JS が落ちてくる。

## なぜこれが効くのか

three.js は圧縮後でも数百 KB ある。全ページの先頭で読み込むとサイトが遅くなる。

`client:visible` を使うと、訪問者がその 3D ビューまでスクロールして初めてダウンロードが始まる。ページ上部のテキストは即座に表示されるので、体感速度は落ちない。

```astro
<ThreeScene client:visible />
```

書くのはこれだけ。

## ディレクティブの選択肢

| ディレクティブ | いつ JS を読むか |
|---|---|
| （なし） | 読まない。静的な HTML として描画されるだけ |
| `client:load` | ページ表示と同時にすぐ |
| `client:idle` | ブラウザの手が空いてから |
| `client:visible` | 画面に入ったとき |
| `client:media="..."` | 画面幅などの条件を満たしたとき |

## 静的サイトでも 3D は動く

ひとつ誤解しやすいのは、「静的サイト」と「JavaScript が動かない」は別の話だということ。

| | GitHub Pages で |
|---|---|
| ブラウザで動く JS | 何でも動く（3D、グラフ、アニメーション） |
| サーバーで動く処理 | 動かない（ログイン、フォーム送信、DB） |

「ゼロ JS」は**余計な JS を勝手に送らない**という意味であって、送れないわけではない。必要なところに必要な分だけ送る、というのが設計思想だと理解した。
